## D3 details — LLM provider

The brief assumed the Anthropic API. Replaced by an `LlmProvider` interface (server only):

| Provider | Role |
|---|---|
| `mock` | default; recorded responses in `fixtures/`, no network |
| `claude-cli` | primary live provider: the server spawns Claude Code in print mode (`claude -p`, `--json-schema` for structured output), authenticated with the user's subscription |
| `local` | optional; local model server, to be compared in M2 (8 GB VRAM limits it to small quantized vision models) |

Consequences:
- The PC must be on and logged into Claude Code while the phone uses the app.
- The ledger records time and token counts (if the CLI reports them) instead of dollar cost.
- Subscription use is meant for the user's personal use; if the app is ever used by others, this must be re-checked against Anthropic's terms.
- Exact CLI flags for image input and the JSON output shape are verified at the start of M2 (see `docs/models.md`).

| D23 | Visual check: blocking only | (2026-11-06) The judge reported problems in **every** live check (7 of 7 judged lines in the ledger, 5 from the pipeline and 2 from the CLI, 2–7 problems each), so nearly every lesson was generated twice (≈0.5 $ list price, 1–2.5 min more), and the second scene was not always better (the Germanic-peoples timeline kept the same floating labels). Now each problem has a **severity** in the judge's JSON schema (`{ problems: [{ chapter, severity: "blocking" \| "minor", what, fix }] }`; `ok` dropped, derived). **Blocking** = wrong subject/apparatus/template or a placeholder; a key object the narration talks about missing; content that contradicts the page or teaches something wrong (clock not showing the time read aloud, movable pulley above its load); chapter impossible to follow (key objects/labels hidden, cut off, unreadable, covering each other; empty/black scene). **Minor** = a label a bit off or on a neighbour while the screen still makes clear what is what, duplicated labels, slight readable overlaps, leftovers that do not mislead, framing; "when unsure, minor" (prompt with examples). Only **≥ 1 blocking** problem regenerates (once, as before); minor ones go to the repair request only then, marked "(minor, fix if easy)"; minor-only = `ok`, logged. Unknown/missing severity counts as minor; an answer without a problems array = check skipped (never a regeneration). Ledger `check` line: `problems` (total), `blocking`, `minor`; note prefixed `minor` when nothing blocks. Calibration (8 judge calls, ≈0.73 $ list, re-rendered saved lessons): blocking where the scene really was broken (lab beaker+cube on the communicating-vessels page, pulleys with the load above the movable pulley, daily-routine clock without the hour hand), pass (minor only) on 4 of the 5 regenerated live lessons, one of them after a prompt clarification for a false blocking (a leader line ending on the neighbouring arrow). **Cache key unchanged (`check-1`)**: the cache stores only final lessons and the check only got looser, so lessons cached under the stricter rule stay valid. The generation prompt is unchanged (recordings valid). |
